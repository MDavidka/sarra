Welcome to Syte

A self-hostable autonomous deployment platform, zero-downtime runner, and embedded AI builder operating directly on your Linux servers.

Platform Overview

Syte combines containerized application hosting with an embedded Autonomous AI Engineer directly in your virtual machines. Deploy repositories with git, run zero-downtime blue/green deployments, provision automatic SSL certificates via Caddy, and manage state in Linux VM.

QuickStart: Install

Get Syte running on any Linux server (Ubuntu, Debian, AlmaLinux, Rocky) in under 60 seconds.

1. One-Line Automated Installer

Run the automated installation script on your server as root:

install.sh Terminal Command 
curl -sSL https://raw.githubusercontent.com/MDavidka/sarra/main/install.sh | bash

2. What the Installer Configures

  • Python 3 Virtualenv: Creates an isolated environment under /root/syte/.venv.
  • Caddy Reverse Proxy: Automatic ingress on ports 80 (HTTP) and 443 (HTTPS).
  • Systemd Unit: Registers syte.service to automatically boot with system recovery.
  • Dashboard Port: Syte dashboard listens directly on port 8787.

3. Accessing the Dashboard

Once installation finishes, visit your browser at:

http://<your-server-ip>:8787

QuickStart: Update

Keep your Syte deployment engine, Caddy configs, and AI builder up-to-date with seamless zero-loss self-updates.

1. Updating via CLI Script

Run the built-in update utility from the root directory:

bash /root/syte/scripts/update.sh 
bash /root/syte/scripts/update.sh

2. Update Execution Pipeline

  1. Git Sync: Resolves upstream git remote target and fast-forwards the branch.
  2. Dependency Resolution: Updates Python virtualenv with pip install -r requirements.txt.
  3. Database Migrations: Automatically applies SQLite schema migrations in /root/syte/syte/database.py.
  4. Caddy Reload: Synchronizes active domain reverse proxy blocks.
  5. Graceful Service Restart: Re-executes syte.service without dropping traffic to hosted apps.

3. Updating from the Web UI

You can also navigate to Settings → System → Check for Updates in the Syte web dashboard to trigger one-click background updates.

Manage the Syte systemd daemon, reload Caddy proxies, and free port collisions cleanly.

Git: Connect

Connect GitHub repositories, private git URLs, and deploy branches straight to isolated server runtimes.

1. Connecting Repositories

Syte supports multiple connection protocols for deploying repositories:

  • Public Git URLs: Any HTTPS repository URL (e.g. https://github.com/user/repo.git).

2. Workspace Git Structure

When you create a project, Syte provisions a dedicated directory on the filesystem:

filesystem /var/lib/syte/workspaces/{project_id}/

Next: Cloudflare
Cloudflare DNS-01 API token setup for wildcard and proxied TLS.

Domain: Cloudflare

Leverage Cloudflare DNS-01 challenge automation to issue wildcard certificates for all preview & production subdomains.

1. Obtaining Cloudflare API Token

  1. Log in to your Cloudflare Dashboard → My Profile → API Tokens.
  2. Click Create Token → select template Edit zone DNS.
  3. Set permissions: Zone - DNS - Edit and Zone - Zone - Read.
  4. Include Zone: All zones or select specific domain zones.
  5. Copy the generated API token.

2. Setting Cloudflare Token in Syte

Add the token in Settings → System Settings → Cloudflare API Token or export in environment:

export CLOUDFLARE_API_TOKEN="your-cloudflare-api-token"

3. Cloudflare Proxy (Orange Cloud vs Grey Cloud)

  • DNS-Only (Grey Cloud): Recommended for direct Caddy TLS termination and zero-latency WebSocket/SSE connections.
  • Proxied (Orange Cloud): If using Cloudflare proxy, set SSL mode in Cloudflare to Full (Strict).

Next: SSL
Automatic Let's Encrypt certificates and TLS rotation.

Domain: SSL

Zero-configuration, automated HTTPS certificate issuance with Let's Encrypt and ZeroSSL.

1. How SSL Provisioning Operates

Syte relies on Caddy's automated ACME engine to issue and renew certificates:

  • HTTP-01 Challenge: Automatically triggered on port 80 when a new domain is attached.
  • DNS-01 Challenge: Used for wildcard domains (*.syte.domain.com) via Cloudflare API.
  • Auto-Renewal: Certificates are automatically renewed 30 days prior to expiration with zero manual intervention.
  • OCSP Stapling: Always enabled by default for maximum handshake speed and security.

2. Checking SSL Status

In the project dashboard, the domain badge indicates live certificate status: Valid (TLS 1.3).

Next: How Caddy Works
Understanding reverse proxy routing, Caddyfile generation, and upstream ports.

Domain: How Caddy Works

Deep dive into Syte's unified Caddy reverse proxy architecture, route generation, and dynamic port mapping.

1. Ingress Architecture Flow

Caddy acts as the public gatekeeper on ports 80 and 443, routing requests directly to the dedicated loopback port of each application process:

Caddyfile /etc/caddy/Caddyfile 
# Production App Route
app.example.com {
    reverse_proxy 127.0.0.1:3000
}

# Branch Preview Route
feat-ui.app.example.com {
    reverse_proxy 127.0.0.1:4002
}

2. Dynamic Reloading via Syte Engine

Whenever an application is deployed, a preview server is spawned, or a domain is attached, Syte's syte/caddy_routes.py updates the unified route table and reloads Caddy dynamically in ~12ms without closing active TCP sockets.

Environment Variables: What is an Env?

Understanding environment variables, separation of config from code, and zero-knowledge secret isolation.

1. The Twelve-Factor Config Principle

An application's config is everything that is likely to vary between deploys (staging, production, developer environments). This includes:

  • Resource handles to databases (DATABASE_URL, REDIS_URL).
  • Credentials to external services (AWS_SECRET_ACCESS_KEY, STRIPE_API_KEY).
  • Per-deploy values such as canonical hostnames (NEXT_PUBLIC_APP_URL).
Never Commit Secrets to Git Keep passwords and API tokens out of repository code. Syte injects environment variables securely into process memory at launch time.

Define system-wide environment variables shared across all hosted projects on the server.

AI: How It Works

The OpenCode-inspired autonomous engine orchestrating planning, code generation, AST linting, and live preview verification.

1. The 4-Phase Autonomous Execution Loop

  1. Planning Phase: AI analyzes the prompt and project codebase, outputting a structured plan.md with numbered actionable steps.
  2. Interactive Countdown: A 10-second auto-start countdown card is rendered in the UI, allowing the user to approve, pause, or edit the plan.
  3. Multi-Turn Tool Execution: The agent executes specialized tools directly inside the project directory:
    • read_file & write_file
    • replace_file_content (surgical block diffs)
    • run_shell_command (safe sandbox execution)
    • check_syntax (deterministic AST scanner)
  4. Live Preview Verification: Spawns the isolated dev server and checks HTTP status & console logs before concluding the turn.

Theme: Server Swarm → Setup a Server
Orchestrate multiple Linux servers under a single unified control plane.

Server Swarm: Setup a Server

Bootstrap a master control plane server to coordinate multiple worker nodes across cloud providers.

1. Swarm Control Plane Concept

A Syte Swarm connects multiple distinct Linux machines (Hetzner, AWS EC2, DigitalOcean, bare-metal homelabs) under one dashboard:

  • Leader Node: Hosts the central SQLite/Postgres database, user authentication, and web interface on port 8787.
  • Worker Nodes: Execute build workloads, host container runtimes, and terminate edge TLS for assigned domains.

2. Server Requirements

  • Operating System: Ubuntu 22.04+, Debian 12+, AlmaLinux 9+, or Rocky Linux 9+.
  • RAM: 2GB+ (4GB recommended for heavy Next.js / Turbopack builds).
  • Ports open: 80, 443, 8787.

Next: Prev / Prod
Dual-port blue/green switching, staging previews, and production isolation.

Application: Prev / Prod

Dual-port blue/green zero-downtime production deployment alongside instant live development previews.

1. Production vs Preview Separation

  • Production Server (Blue/Green): Serves main traffic on dedicated production ports (3000-3999). When a new build arrives, it boots on an alternate green port, passes HTTP health checks, and Caddy dynamically swaps traffic with zero dropped requests.
  • Preview Server (Live Dev / HMR): Runs in parallel on preview ports (4000-4999). Used by the AI builder and git branches for hot-reloading testing without affecting live users.

2. Port Allocation Table

[Production Traffic] : Domain app.com  → Caddy :443 → 127.0.0.1:3000 (Active Blue)
[Staging / Preview]  : Domain feat.com → Caddy :443 → 127.0.0.1:4002 (Preview Dev)

POST /ai/stream

Proper real-time API for streaming autonomous agent thoughts, message token deltas, tool executions, and status updates directly to external applications via Server-Sent Events (SSE).

Real-Time Streaming Specification

The stream returns text/event-stream. External clients consume events continuously as the agent operates on the host VM:

  • event: thought — Live reasoning / thinking stream from reasoning models.
  • event: token — Text content token delta as it is generated.
  • event: status — Human-readable progress notification (e.g. creating files, running AST scans).
  • event: tool_call_start — Emitted when a tool commences execution.
  • event: tool_call_result — Result payload returned from tool execution.
  • event: done — Agent execution finished successfully.
  • event: error — Error payload if communication or syntax fails.
Authentication: Bearer Token or X-API-Key Content-Type: application/json
POST/api/ai/stream
Authorization & Headers
JSON Payload

Streaming to External Apps (TypeScript / Node.js)

client.ts External App Consumer 
const response = await fetch("http://<your-server-ip>:8787/api/ai/stream", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "X-API-Key": "syte_your_token_here"
  },
  body: JSON.stringify({
    message: "Scaffold a React feedback widget",
    model: "gpt-4o"
  })
});

const reader = response.body?.getReader();
const decoder = new TextDecoder();

while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  const chunk = decoder.decode(value);
  console.log("Received SSE Event:", chunk);
}

PUT & GET /ai/settings

Bi-directional host communication to set active model, update agent parameters, ask configuration changes, or tune execution speed.

Host Communication Parameters

  • model: The active model ID (e.g. gpt-4o, claude-3-5-sonnet-20241022, deepseek-chat).
